# Labeler next, revert, and calibration load

The actions stack in one column: **Save** beside the trash button, then **Save and next**, **Next →**, and **Revert changes ↫**. All four use the normal blue.

- **Next →** shows the next view of the current frame; from the last view (or in a single-view project) it opens the next frame in the combined list (labeled frames, then remaining frames). It does not save. Edits stay on the frame you left. The button is inactive only on the last view of the last frame. (PR paninski-lab/lightning-pose-app#189. Until #152 it always opened the next frame and never changed view; that was reversed to match **Save and next**.)
- **← Back** (beside Next; paninski-lab/lightning-pose-app#147, same PR) mirrors Next: previous view of the frame; from the first view it opens the previous frame in the combined list on its **last view**. It does not save. Inactive only on the first view of the first frame. Page: `hasPreviousFrame` input and `previousFrame` output; `handleNextFrame` / `handlePreviousFrame` share `openFrameAtOffset`. Keyboard shortcuts for Back/Next (optional in #147) are not done.
- **Clear values** (paninski-lab/lightning-pose-app#151, same PR; `aria-label` "Clear values in this view") unplaces every keypoint in the selected view only (`FVUtils.clearKeypoints`). No confirmation: nothing is saved until Save, and Revert undoes it. Inactive when the view has no placed keypoint.
- When **Next** or **Save and next** moves on from the last view, the next frame opens on its **first view**, labeled or not. Before, a labeled frame kept the view you were on, so a second press skipped a whole frame. Clicking a frame in the list still keeps the current view. Implementation: `openFrameOn` ('first' after Next / Save and next, 'last' after Back) in `labeler-center-panel.component.ts`, consumed in `ngOnChanges` when the frame input changes.
- **Keep selected keypoint** (switch labeled "Keep selected", off by default, `labeler-view-options.keepSelectedKeypoint` in localStorage; paninski-lab/lightning-pose-app#153): when on, changing view (filmstrip, Next, Save and next) and opening the next frame, including a remaining frame, keep the selected keypoint if the view has it; otherwise the first keypoint is selected. One helper, `selectKeypointForView()`, replaced `selectFirstKeypoint()`.
- **Placement:** Keep selected (left) and Clear values (right) sit in a bar at the top of the open Keypoints panel, outside the scrolling list (`data-testid="keypoint-tools"`). Clear view was first in the panel header and Keep selected in View options; Jordan moved them because a click on the header is meant to collapse the panel, and neither control is a view option. `.app-accordion-content` has `overflow: hidden`, which cuts tooltips off at the panel edges, so Clear values has none and Keep selected's tip ("Keep the selected keypoint when switching views and frames.") opens below, starts at the label's left edge (`tooltip-bottom tooltip-start`), and is capped at 14rem (`before:max-w-56`). Wording only, no test; not yet checked in the browser.
- **View options groups:** Context, Image, Keypoints, Skeleton (`role="group"` with an `aria-label` each, no visible heading; Jordan tried headings and preferred plain dividers), a divider between groups, then a divider and Pixel grid overlay. Clear values is `btn-error btn-soft` with a `close` (✕) icon, like Delete under it. Keypoint size, Keypoint labels, Keypoint label size and Pixel grid overlay got `aria-label`s.
- **Revert changes ↫** is active only when this frame has edits. On a labeled frame it restores the saved keypoints. On a remaining frame it clears every point, including sidecar predictions, and leaves the frame in **Remaining frames to label**.

Both remove-frame buttons are the red trash icon. The tooltip still says whether the frame leaves the label file or the labeling queue.

**Load Calibration** sits at the top of **Multiview tools**, then **Refine calibration**, then **Project keypoints to all views**. It uses the File Manager dialog. It copies `.toml` files into `calibrations/`. The name before `.toml` is the session id. An existing file is left unchanged. After a copy, the calibration status for the current session is checked again.

`labeler-center-panel.component.spec.ts` "Next and keypoint selection" guards Next walking the views and then opening the next frame on its first view without saving, Save and next doing the same from the last view, Back walking back to the previous frame's last view, Clear values emptying only the selected view, and the Keep selected keypoint switch. "side panel" guards the bar above the list and the View options groups. `frame.model.spec.ts` "FVUtils.clearKeypoints" guards clearing one view and Revert restoring it. `frame.model.spec.ts` (`reverts labeled frames to saved keypoints and clears unlabeled frames`) guards a labeled restore that does not alias the saved copy, and an unlabeled clear that stays unsaved. `labeler-page.component.spec.ts` (`next frame follows the combined list without saving`) guards moving from the last labeled frame into the first remaining frame without discarding the edit.
