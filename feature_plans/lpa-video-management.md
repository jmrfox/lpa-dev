# LPA video file management

Let a user import videos that are already on the server, and manage the videos already in a project: list them, flag names, check all-intra encoding, convert, and rename.

## Import session

The live **Choose videos** control is `app-session-import` (Viewer “Upload a new session”, extract frames, and run inference). The choose row is `app-file-source-chooser`. **Server files** defaults to off. Off uses the browser file picker. On opens `app-server-video-picker`, filtered to video extensions, and more than one file can be chosen. Load Calibration uses the same chooser for `.toml`.

- One button. A **Server files** checkbox beside it defaults to off.
- Off: the browser file picker (the user’s machine), then `UploadVideo` and `TranscodeVideo` with `uploads://`.
- On: `app-server-video-picker` browses the server, starting at the project data directory and staying under the home directory. Chosen files skip upload and call `TranscodeVideo` with the absolute path. Output is still `<data_dir>/videos/<stem>.mp4`. The source file is not deleted.

Filename rules are shared with the File Manager videos panel via `parseVideoFilename`.

## File Manager

A **File Manager** screen next to Labeler, Models, and Viewer in the top screen list (`project/:projectKey/files`). It is not a card on the project home screen. Project settings no longer has a Videos tab.

The page is a vertical stack of five panels. Nothing on the page plays images or video. There is no description under the page title. Each panel title, then a collapsed **Help** chip (the marker sits beside the word), then a button row, then the file list. Help starts closed. The explanation is a few sentences, then one bullet for each button, with the button name in bold. **Refresh** reloads that panel's list. The left side of the button row is global. The green **Add** button is first: **Add Label File**, **Add Video**, **Add Model**, or **Add Calibration**, then the blue buttons **Refresh**, **Validate All**, **Check All Encodings**, and **Process All**. The right side needs a selected row. **Rename Selected**, **Check Selected Encoding**, and **Process Selected** are blue. **Delete Selected** is red.

1. **Label Data (CSV)** — CSV files directly in the data directory (`Config.LABEL_CSV_SCOPE` `"root"`; `"tree"` also includes subfolders). The project model directory and a `models` folder in the data directory are excluded.
2. **Videos** — the former settings videos UI. Between Help and the buttons, a heading **Video directories (`videos*/`)** sits above every direct child of the data directory whose name starts with `videos`, including when that list is empty. Each folder has a checkbox. Unchecked folders are remembered until the app restarts. They stay on disk and are left out of this list, the Viewer, inference, and project stats.
3. **Labeled Image Folders** — directories directly under `labeled-data/`.
4. **Models** — directories in the model directory, including folders the Models page does not treat as a model.
5. **Camera Calibration** — `calibration.toml` at the data directory and `calibrations/<session>.toml`. Files in `calibrations/backups/` are not listed. The session id is the labeled-data folder name before the last `_`. On a single-view project (one view, or none), the sentence "This project is single-view, so camera calibration is not used." sits under the title, outside Help, and the rest of the panel is disabled, including **Refresh**. **Add Calibration** asks whether to write one project file or session files. A project file is renamed to `calibration.toml` in the data directory, whatever the source file is named, and that request does not create `calibrations/`. A session file keeps its name in `calibrations/<name>.toml`, creating that folder when it is missing. The name before `.toml` is the session id and uses the same character rule as rename. A local file is uploaded. A server file must be a `.toml` under the home directory and is copied; the source is not moved or deleted. A bad session name returns 400 and is not written. If the destination already exists, the request returns 409 until the dialog is confirmed. **Yes** sends overwrite, which writes a temp file in the same folder and then replaces the destination, so a failed copy leaves the old file in place. **No** leaves that file unchanged, and other chosen session files still proceed. After a file is written, the same camera-group check as **Validate All** runs for that file, and the response includes any problems. The file stays on disk. The File Manager list then refreshes and shows that check. The Viewer **Upload a calibration file** button, under **Upload a new session**, opens the same dialog and is disabled on a single-view project. **Validate All** loads each file with `CameraGroup` and, when the project has views, requires the camera names to match those views in order. **Rename Selected** renames a file inside `calibrations/`. `calibration.toml` keeps that name.

Video files use one rule, shared by the Viewer session list, this videos panel, inference, and project stats: a video folder is a direct child of the data directory whose name starts with `videos`, unless that folder is unchecked in File Manager for this app session. Playable sessions are `videos*/**/*.mp4` under the folders that are still checked, including nested files such as `videos-for-each-labeled-frame/<session>/*.mp4`. The Viewer info tooltip says that, and that folders unchecked in File Manager are skipped until the app restarts. The videos panel also lists `.avi`, `.mov`, `.mkv`, and `.webm` in the checked folders so they can be converted.

- Names are checked on every refresh. Single-view: `session.ext`. Multiview: `session_view.ext` (last `_`). A view segment that is not a configured view is flagged. Invalid characters and a missing extension are flagged the same way as import. A problem is shown beside that filename. This panel has no Validate button, and the check does not probe all-intra.
- **Check All Encodings** and **Check Selected Encoding** use the existing `ffprobe` RPC. Non-mp4 files are marked as needing conversion.
- **Process Selected** and **Process All** replace a file with an all-intra copy in the same folder. All-intra encoding is optimal for analysis. **Process All** asks before it starts, because it may take a long time, and checks first when status is unknown. Conversion reuses the upload ffmpeg options (`-g 1`) through `GET /app/v0/sse/TranscodeVideoInPlace`: the file must already be under a `videos*` folder, a temp sibling is written, then the original is replaced in the same folder. Status is keyed by the full path.
- **Add Video** opens the same Import Session screen as the Viewer. New files land in `videos/` and show up in this list after the dialog closes.
- **Rename Selected** uses `POST /app/v0/rpc/RenameVideo`. The new name stays in the same folder, must pass `parse_session_view`, and conflicts return 409. Prediction and label files are not renamed.

**Validate All** on the other panels calls `POST /app/v0/rpc/validateProjectFiles`. **Rename Selected** on those panels:

- Label CSVs: any `.csv` name. A file is invalid only when it cannot be read as a label table (three header rows, and at least one bodypart with both `x` and `y`). A missing frame, an index path that is not `labeled-data/<dir>/<name><digits>.png` or `.jpg`, a bodypart that lacks `x` or `y` while another is complete, and bodyparts that do not match project keypoints are warnings. A warning does not remove the file from the labeler. **Add Label File** copies one or more `.csv` files onto the data-directory root. A local file is uploaded. A server file must be a `.csv` under the home directory and is copied; the source is not moved. A name that is not a `.csv` returns 400 and is not written. If that filename already exists, the request returns 409 and the existing file is left unchanged. Each chosen file is its own copy. After a file is written, the same header and index check as **Validate All** runs. The file stays on disk. The dialog reports a header failure as an error and other problems as a warning. The panel then refreshes. Rename (`POST /app/v0/rpc/renameLabelFile`) keeps the file in its current folder, requires a `.csv` filename, and does not rewrite the CSV. A collision returns 409.
- Labeled-data directories: `session` or `session_view`, with frame images directly inside. Another subdirectory or a non-image file is an issue. A loose file in `labeled-data/` is an issue. Rename (`POST /app/v0/rpc/renameLabeledDataFolder`) keeps the folder inside `labeled-data/` and rewrites label CSV index paths from `labeled-data/<old>/` to `labeled-data/<new>/`. The edit touches only the first field after the three header rows, so a name like `old_extra` is left alone and numbers stay as stored. CSVs in the model directory are not rewritten. If a CSV write fails, the original text is restored and the folder is moved back. A loose file is renamed in place, and only an index that equals that exact path is updated.
- Model directories: the create-model filename rule, readable `config.yaml` or `ensemble.yaml` (not both, not neither), `train_status.json` with a `status` field when present, and `video_preds/` as a directory of `session.csv` or `session_view.csv` when present. **Add Model** copies one directory to `model_dir/<folder name>`. A local folder is uploaded. A server folder must be under the home directory and is copied; the source is not moved. The folder name must pass the model-name rule. If that folder already exists, the request returns 409 and nothing is replaced. The source must not be the destination or sit inside it. After the copy, the same model check as **Validate All** runs. The folder stays on disk, and the dialog reports any problems. The panel then refreshes. Rename uses the Models page dialog and `renameModel`, which moves the directory to `model_dir/<new name>`. **Delete Selected** opens that page's delete dialog. The user types the model path, and `deleteModel` removes the folder only when that text matches and the folder is strictly inside the model directory.

## Tests

- `app_server/tests/routes/test_videos.py`
  - `test_transcode_in_place_replaces_videos_test_file`: in-place transcode replaces a `videos_test` file and does not copy it into `videos/`.
  - `test_rename_video_accepts_valid_name_rejects_bad_name_and_collision`: rename accepts a valid name, rejects a bad name, and returns 409 when the target exists.
  - `test_resolve_project_video_accepts_any_videos_prefix_dir`: a nested file under `videos-for-each-labeled-frame/` is accepted; a file whose top folder does not start with `videos` is rejected.
  - `test_ignored_video_dir_is_omitted_from_project_videos`: a nested mp4 under an ignored `videos*` folder is absent from `iter_project_mp4s`, and `project_video_root` rejects it; a sibling `videos` folder is still included.
- `app_server/tests/routes/test_validate_project_files.py`
  - `test_validate_label_csv_hides_only_unusable_files`: a readable root CSV with a missing image is a warning and `findLabelFiles` still returns it; a file that is not a label table is omitted; a CSV in a subdirectory is omitted while `LABEL_CSV_SCOPE` is `"root"`.
  - `test_validate_label_csv_flags_bad_header`: a `CollectedData_<view>.csv` with a bad header is reported, a well-formed one is not, and a CSV under `models/` is omitted when the project model directory is elsewhere.
  - `test_validate_calibration_toml_flags_missing_camera_field`: a `calibrations/<session>.toml` that `CameraGroup` cannot load is reported, and a file whose cameras match the project views is not.
- `web_ui/src/app/session-import/session-import.component.spec.ts`: the server-files checkbox defaults off, and when it is on, Choose videos does not open the local file input.
- `app_server/tests/routes/test_rename_project_files.py`
  - `test_rename_labeled_data_folder_rewrites_csv_paths`: a valid folder rename updates `labeled-data/old/img0001.png` and leaves `labeled-data/old_extra/...` and the three header lines unchanged; a bad new name is rejected and nothing moves.
  - `test_import_calibration_creates_folder_and_copies_toml`: a server `.toml` is copied into a new `calibrations/` directory and a file `CameraGroup` cannot load reports a format issue; a second import of the same name returns 409 with the first file unchanged.
  - `test_import_calibration_project_file_and_overwrite`: a project-file copy lands at `calibration.toml` and does not create `calibrations/`; a second copy without overwrite returns 409, and a copy with overwrite replaces the contents.
  - `test_import_label_and_model_copy_without_overwrite`: a CollectedData CSV is copied onto the data-directory root and a model folder is copied under the model directory; a second copy of either name returns 409 and leaves the first copy unchanged.
- `web_ui/src/app/file-manager/project-videos/project-videos.component.spec.ts`: a multiview name without `_` is flagged, `session_view.mp4` is accepted when that view is configured, and a nested `videos-for-each-labeled-frame/.../clip.mp4` stays in the list with that filename error shown and no Validate button.
- `web_ui/src/app/file-manager/file-listing.spec.ts`: **Validate All** keeps the on-screen file order when validation returns a different order.
- `app_server/tests/routes/test_delete_model.py`
  - `test_delete_model_requires_typed_path_and_stays_inside_model_dir`: a wrong confirmation leaves the folder, a path outside the model directory is refused, and the matching confirmation removes only that model folder.
